# PostgreSQL Structure and definitions

Current source builds add PostgreSQL structural DDL to the existing **Structure** view. Open a table and choose Structure to inspect columns, indexes, foreign keys, constraints, user triggers, native table statistics and the definition. Inspection reads native metadata only; it never runs the definition or changes the connection's transaction/search path. Downloadable Preview 1 is unchanged.

Ordinary tables show quoted schema/table/column names, exact native types and modifiers, defaults, NOT NULL, explicit collations, stored/virtual generated expressions, identity generation/options and named primary/unique/foreign/check/exclusion constraints. Dropped columns are excluded. Unlogged/temporary persistence is retained. Row-level security enable/force flags are retained; policy definitions must be supplied separately.

Views show native SELECT definitions, explicit output names and view options, including security barriers/invoker and check options. Materialized views now appear in the lazy PostgreSQL catalog with native columns and read-only row inspection. Their DDL uses **WITH NO DATA**, so creating a copy never automatically runs its SELECT. Refresh it explicitly before browsing a newly created unpopulated view.

This is a structural definition, not a database backup: referenced types/functions/sequences must already exist. Owners, grants, policy definitions, sequence state, table/materialized-view storage options, view-column defaults and dependency ordering are excluded. Indexes and triggers remain in their separate Structure sections. Partitioned, inherited and foreign-table DDL currently shows an explicit unavailable notice; their ordinary metadata remains accessible. Definitions above the 2 MiB viewer limit show a notice instead of a truncated SQL script. Use PostgreSQL's dump tools for full recreation/migration.

Implementation independently uses [native PostgreSQL definition functions](https://www.postgresql.org/docs/16/functions-info.html), [column catalogs](https://www.postgresql.org/docs/16/catalog-pg-attribute.html) and [view options](https://www.postgresql.org/docs/16/sql-createview.html). No reference implementation or commercial source is copied. Actual validation and platform/package scope belong in [VALIDATION.md](VALIDATION.md).

Real PostgreSQL definition roundtrip/read-only/session-preservation checks and configured local validation gates pass. The actual macOS source debug app also verifies native table/view/materialized Structure, exact numeric results and disabled view editing. It replays the observed identity/generated-column definition through the normal editor in a fresh synthetic schema, verifies the identity/default/generated values and inspects identical recreated DDL. Updated optimized packages and Windows/Linux acceptance remain pending.

Generated identity definitions now use the editor-supported INCREMENT/MINVALUE/MAXVALUE/START/CACHE/CYCLE order, so the identity clause passes the same parser guard used by editor execution. Real PostgreSQL core checks recreate the displayed identity/generated-column definition and compare native columns and DDL. Handwritten identity options in other PostgreSQL-valid orders may still be refused; broader native DDL parsing remains pending. For views, use the equivalent `WITH (check_option=local)` option when trailing `WITH LOCAL CHECK OPTION` is refused. Inspection itself does not execute any of these definitions.

## Table statistics (source builds)

Open a PostgreSQL ordinary table or materialized view and choose **Structure → Statistics**. The inspector shows the planner row estimate and native table, index and total storage in bytes. Values retain the server text through IPC, including sizes above JavaScript's safe integer range. A never-analyzed table shows **Unavailable** for its estimate.

Row estimates can be stale; they are not live counts. Table storage includes auxiliary/TOAST storage and excludes attached indexes; total storage includes both. Inspection reads catalog estimates and native size functions, never scans rows or runs ANALYZE, and preserves an existing read-only transaction. Reopen the table from the explorer to reread its statistics. Ordinary views, partitioned parents, foreign tables and other engines currently omit this section. A selected ordinary partition reports its own storage, not the parent's aggregate. Preview 1 and the current Preview 2 candidate do not contain this change.

The original implementation uses PostgreSQL's [planner relation estimates](https://www.postgresql.org/docs/16/catalog-pg-class.html) and [native size functions](https://www.postgresql.org/docs/16/functions-admin.html#FUNCTIONS-ADMIN-DBSIZE). The current native macOS source app verifies an ordinary table’s Statistics section through Tauri IPC against a real TLS PostgreSQL fixture. Real-server tests additionally cover unknown estimates, materialized views and read-only transactions; those specific native interactions and updated packages remain pending. See the validation record.
