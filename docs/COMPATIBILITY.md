PostgreSQL simple-protocol results preserve server text and NULL; binary/date/JSON/array values currently appear as text unless inspected as JSON. Typed codecs are a follow-up. No claim of CockroachDB or Redshift compatibility follows merely from PostgreSQL wire compatibility.

Manual reconnect requires confirmation in Rust, closes the existing session/tunnel and opens a fresh session with the saved configuration. Uncommitted transactions, temporary tables and session settings are reset; queries are never replayed. Completed result spools remain readable/exportable, while cached table editability is invalidated. Failed setup leaves the connection closed. Real SQLite/PostgreSQL/MySQL/MariaDB contracts cover native rollback/reset, old query/import cancellation and failure recovery; packaged macOS SQLite reconnect also verifies rollback, staged-edit refusal, retained results and stale-edit invalidation. Other engines’ native reconnect and Windows/Linux interaction remain pending. See [connection behavior](TLS.md).

MySQL/MariaDB preserves integer and decimal text exactly as tagged numbers, distinguishes binary columns and NULL, and keeps one dedicated user session for manual transactions. Non-UTF-8 result text is preserved as binary bytes; automatic legacy-charset decoding remains pending. MySQL JSON protocol values use the typed JSON viewer; MariaDB JSON aliases appear as text. Cancellation falls back to closing the session if interruption cannot be confirmed within three seconds; reconnect is then required. Real verified-TLS contracts pass on PostgreSQL, MySQL and MariaDB, including custom CA bundles, hostname rejection and cancellation. Certificate-required PostgreSQL/MySQL/MariaDB contracts also pass with encrypted PKCS#12 identities. Single-bastion SSH forwarding supports agent, private-key and password authentication with an explicit SHA256 host-key pin. Real OpenSSH plus database mTLS contracts cover all three server engines; see [SSH configuration and current limits](SSH.md). Server connections expose a 1–300-second setup deadline (default 10), consistently used by Connect and Test connection. Query/metadata deadlines are separate. See [TLS and connection configuration](TLS.md).

Table-opening views offer server-side column filters, sorting and 100/250/500-row database pages. Native SQL is shown in the editor. Primary keys provide default order and break explicit sort ties; tables without keys can have unstable ties. OFFSET paging is a fresh query, not a frozen snapshot: concurrent writes can shift page boundaries, and deep offsets can be expensive. The grid’s separate quick text filter and header sorting remain local to the fetched page. Ad-hoc SQL retains disk-spool pagination and the configured row limit. Export includes only the rows retained by the configured row limit. Native exports stream one row at a time from the result spool; the 8 MiB UI page bound does not limit the exported file. JSON/JSONL exports use `{columns, values}` with tagged cells to preserve duplicate names, NULL and large integers. SQL INSERT exports use the source engine’s identifier, text and binary literal syntax. Real SQLite/PostgreSQL/MySQL/MariaDB roundtrips retain the native cell values; PostgreSQL’s simple-protocol text shape remains unchanged.

Table editing is enabled only for the built-in table-opening SELECT and matching full column order. Ad-hoc SQL results remain read-only. Updates/deletes require a non-NULL primary key and compare every original value; a stale row cancels the entire batch. Views and generated columns cannot be directly changed. Batches are bounded to 1,000 changes / 8 MiB. Inserts can omit columns for database defaults. Savepoints preserve an existing manual transaction; after editing its changes require an explicit COMMIT or ROLLBACK. PostgreSQL compares the server's text representation; changing its formatting settings can cause a conservative conflict.

MySQL/MariaDB staged batches require an InnoDB base table and UTF-8 session (`SET NAMES utf8mb4` after changing session encodings). Server metadata is checked while holding the table metadata lock. Bound unsigned integers and decimal text preserve exact values; binary comparisons detect changes hidden by case-insensitive/trailing-space collation. Value-conversion warnings abort the batch. Manual transactions, including `autocommit=0`, remain uncommitted. The 60-second editing deadline interrupts and drains the protocol before rollback; COMMIT acknowledgements are drained without cancelling the commit. An unconfirmed interruption/rollback closes the connection and requires data verification before retrying. MySQL UPDATE affected counts report matched rows, including unchanged values.

Transaction guarantees follow the server: nontransactional trigger writes and external side effects cannot be undone by a savepoint. Rollback warnings are surfaced rather than reported as atomic success. Server formatting/encoding changes may produce conservative conflicts; refresh before editing.

The table Structure view shows native constraint and user-trigger metadata. PostgreSQL provides constraint definitions and trigger firing modes; internal enforcement triggers are excluded. MySQL/MariaDB lists constraint names/types and shows their definitions in the table DDL; trigger timing, event and body are displayed without pretending to be a complete backup script. SQLite exposes constraint definitions through its original table DDL and user triggers through sqlite_schema. NULLability remains in the column list. No automatic trigger execution or schema modification occurs during inspection. Metadata visibility follows connection permissions, so an empty list does not prove that a table has no triggers. PostgreSQL trigger functions, structured SQLite CHECK extraction, schema editing and statistics remain pending.

Relationship diagrams use native foreign-key column mappings on SQLite (main schema), PostgreSQL, MySQL/MariaDB and SQL Server source builds, including composite and self-referencing keys. The desktop supports saved layouts, pan/zoom, manual/grid layout and native SVG export. Table selection bounds the diagram to a focused schema area; broader engine support and large-catalog performance validation remain pending. See [diagram behavior and limits](DIAGRAMS.md).

CSV and JSON imports append into editable SQLite/PostgreSQL/MySQL/MariaDB InnoDB tables and SQL Server disk-based base tables in source builds through the same bounded transaction/savepoint writer. JSON supports standard object arrays and the app's explicit typed JSON export format, including positional duplicate source names. NULL and exact number tokens stay in Rust; destination database coercion rules still apply. Real five-engine contracts verify late parse/EOF failures roll back written batches and typed export roundtrips remain pending inside manual transactions. See [the import guide](IMPORTS.md) for input shapes, bounds and numeric limits. SQLite/PostgreSQL/MySQL/MariaDB and SQL Server source-build SQL scripts run from native-picked immutable snapshots with full preflight, mandatory review, completed-statement/batch progress, deadlines/cancellation and the native connection lock held across the file. They preserve script transaction commands and report partial execution rather than promising whole-file rollback. SQL exports retain the source dialect for identifier, text and binary syntax; real five-engine roundtrips pass. Native desktop validation is listed separately in the validation log. JSONL imports remain pending.

DuckDB source builds add the native local-file workflow described in [the DuckDB guide](DUCKDB.md). The existing downloadable Preview 1 does not contain DuckDB. Its native database engine enforces read-only file access, and automatic extension installation/loading plus external file/network SQL access are disabled. Native estimated/runtime JSON plans share the existing tree, raw output and cancellation pipeline. Runtime analysis requires confirmation and is disabled on read-only files. Relationship diagrams and Structure foreign keys use the ordered native catalog, including composite/self-reference metadata and read-only files; cross-schema/catalog foreign keys are rejected by DuckDB. Native desktop diagram interaction remains pending. SQL file imports reuse the shared snapshot/preflight/review/progress workflow, native cancellation and original script transactions; SELECT rows are discarded. Native desktop SQL-file interaction remains pending. Reviewed grid editing and CSV/JSON row imports support scalar base tables, exact bound values, generated-column guards and whole-batch rollback. DuckDB has no savepoints: these writes refuse existing transactions while preserving caller work; COMMIT/ROLLBACK first. Unsupported container/interval write types keep the table noneditable. Native desktop write interaction remains pending. Decimal and top-level 128-bit integers are preserved exactly; unsupported native/container representations require a VARCHAR cast. Windows/Linux DuckDB workflows and package footprint remain pending.

ClickHouse source builds use the native TCP protocol, not HTTP. Precise scalar codecs, native read-only enforcement, selected-database browsing, scoped cancellation and shared result exports are implemented. Nested types need String casts, native result names must be distinct, and affected counts are unavailable. Native estimated SELECT JSON plans expose operators and index details through the shared tree/raw/export workflow, including read-only profiles. Planning can infer external-source schemas; timeout/cancel may close the session when interruption cannot be confirmed. Runtime Analyze is disabled in this driver (verified server 26.3 rejects it), and native desktop plan interaction remains pending. Transactions, imports and reviewed editing remain disabled. See [the ClickHouse guide](CLICKHOUSE.md) for exact behavior and the remaining desktop/platform checks.

SQL Server source builds preserve original T-SQL batches and native result sets, including local variables and empty SELECTs. BIGINT/DECIMAL/NUMERIC cells remain exact; MONEY/SMALLMONEY needs a DECIMAL cast. Arbitrary query affected counts are unavailable, cancellation does not promise rollback, and the row limit may stop later statements in a batch. Read-only validation is a client guard; use restricted server permissions for server enforcement. Reviewed grid edits support disk-based base tables, preserve caller transactions and reject stale rows and lossy numeric/text/binary conversions. Direct edit counts use native OUTPUT, independently of trigger counts; arbitrary query affected counts remain unavailable. CSV/JSON imports reuse the same bound writer and preserve one transaction/savepoint across the entire file; real driver/core rollback, cancellation and timeout contracts pass. The table-wide lock remains through caller transactions. Relationship diagrams retain ordered composite/self/cross-schema keys and reuse shared layouts/SVG export, including read-only connections; real core contracts pass. Native estimated SHOWPLAN_ALL and confirmed runtime STATISTICS PROFILE plans now use the shared bounded tree/raw/Cancel pipeline, including actual operator Rows/Executes, transaction-preserving writes and setting cleanup. Runtime data previews remain bounded while surplus rows are drained. Native desktop plan interaction remains pending; native GO-delimited SQL file imports preserve variable scope, count completed batches and drain SELECT results without a row cap. Broader catalogs remain pending. See [the SQL Server guide](SQLSERVER.md); the published Preview 1 is unchanged.

Source builds offer **Go to SQL error** for trustworthy SQLite/PostgreSQL query positions and supported parser preflight locations. Original error messages remain visible. Submitted statement/selection/batch positions are converted to editor UTF-16 units; editing the source hides its pointer. Internal PostgreSQL queries, generated plans, reframed SQL Server GO preflight batches and errors without a reliable position have no pointer. Other engines' native query positions and updated native desktop acceptance remain pending.

PostgreSQL, MySQL, MariaDB and SQL Server source builds add a lazy function/procedure catalog: native signatures and return types, literal search, 100-row pages, individually loaded definitions and explicit opening in an SQL tab. Read-only inspection never invokes routines. PostgreSQL overloads and MySQL/MariaDB same-name function/procedure identities remain distinct. Native permissions govern visibility; SQL Server encrypted definitions are unavailable. System routines, PostgreSQL aggregates and SQL Server CLR routines are excluded. Other engines' catalogs and new native desktop acceptance remain pending. See [routine browsing](ROUTINES.md).

Redis uses a dedicated capability-driven key workspace rather than SQL tables. Native cursor semantics, exact integers and binary bytes remain intact. Cluster/Sentinel/modules, scripting/transactions, blocking/admin commands and native desktop/SSH acceptance remain pending. See [the Redis guide](REDIS.md).

MongoDB has a dedicated document workspace using the official Rust driver, with exact BSON tags carried as canonical Extended JSON text. Find results retain ordered BSON snapshots for guarded edits; aggregation results, views and time-series are read-only. Each page has at most 100 documents and an 8 MiB serialized reply bound; individual BSON documents are limited to 1 MiB. Filters/pipelines reject server JavaScript and write stages. Single-seed and SRV URLs are accepted, but actual SRV/replica-set acceptance remains pending. Document file import/export, cancellation controls and native desktop/SSH/platform acceptance remain pending. See [the MongoDB guide](MONGODB.md).
