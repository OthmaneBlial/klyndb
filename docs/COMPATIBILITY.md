PostgreSQL simple-protocol results preserve server text and NULL; binary/date/JSON/array values currently appear as text unless inspected as JSON. Typed codecs are a follow-up. No claim of CockroachDB or Redshift compatibility follows merely from PostgreSQL wire compatibility.

Manual reconnect requires confirmation in Rust, closes the existing session/tunnel and opens a fresh session with the saved configuration. Uncommitted transactions, temporary tables and session settings are reset; queries are never replayed. Completed result spools remain readable/exportable, while cached table editability is invalidated. Failed setup leaves the connection closed. Real SQLite/PostgreSQL/MySQL/MariaDB contracts cover native rollback/reset, old query/import cancellation and failure recovery; packaged macOS SQLite reconnect also verifies rollback, staged-edit refusal, retained results and stale-edit invalidation. Other engines’ native reconnect and Windows/Linux interaction remain pending. See [connection behavior](TLS.md).

MySQL/MariaDB preserves integer and decimal text exactly as tagged numbers, distinguishes binary columns and NULL, and keeps one dedicated user session for manual transactions. Non-UTF-8 result text is preserved as binary bytes; automatic legacy-charset decoding remains pending. MySQL JSON protocol values use the typed JSON viewer; MariaDB JSON aliases appear as text. Cancellation falls back to closing the session if interruption cannot be confirmed within three seconds; reconnect is then required. Real verified-TLS contracts pass on PostgreSQL, MySQL and MariaDB, including custom CA bundles, hostname rejection and cancellation. Certificate-required PostgreSQL/MySQL/MariaDB contracts also pass with encrypted PKCS#12 identities. Single-bastion SSH forwarding supports agent, private-key and password authentication with an explicit SHA256 host-key pin. Real OpenSSH plus database mTLS contracts cover all three server engines; see [SSH configuration and current limits](SSH.md). Server connections expose a 1–300-second setup deadline (default 10), consistently used by Connect and Test connection. Query/metadata deadlines are separate. See [TLS and connection configuration](TLS.md).

Table-opening views offer server-side column filters, sorting and 100/250/500-row database pages. Native SQL is shown in the editor. Primary keys provide default order and break explicit sort ties; tables without keys can have unstable ties. OFFSET paging is a fresh query, not a frozen snapshot: concurrent writes can shift page boundaries, and deep offsets can be expensive. The grid’s separate quick text filter and header sorting remain local to the fetched page. Ad-hoc SQL retains disk-spool pagination and the configured row limit. Export includes only the rows retained by the configured row limit. Native exports stream one row at a time from the result spool; the 8 MiB UI page bound does not limit the exported file. JSON/JSONL exports use `{columns, values}` with tagged cells to preserve duplicate names, NULL and large integers. SQL INSERT exports use the source engine’s identifier, text and binary literal syntax. Real SQLite/PostgreSQL/MySQL/MariaDB roundtrips retain the native cell values; PostgreSQL’s simple-protocol text shape remains unchanged.

Table editing is enabled only for the built-in table-opening SELECT and matching full column order. Ad-hoc SQL results remain read-only. Updates/deletes require a non-NULL primary key and compare every original value; a stale row cancels the entire batch. Views and generated columns cannot be directly changed. Batches are bounded to 1,000 changes / 8 MiB. Inserts can omit columns for database defaults. Savepoints preserve an existing manual transaction; after editing its changes require an explicit COMMIT or ROLLBACK. PostgreSQL compares the server's text representation; changing its formatting settings can cause a conservative conflict.

MySQL/MariaDB staged batches require an InnoDB base table and UTF-8 session (`SET NAMES utf8mb4` after changing session encodings). Server metadata is checked while holding the table metadata lock. Bound unsigned integers and decimal text preserve exact values; binary comparisons detect changes hidden by case-insensitive/trailing-space collation. Value-conversion warnings abort the batch. Manual transactions, including `autocommit=0`, remain uncommitted. The 60-second editing deadline interrupts and drains the protocol before rollback; COMMIT acknowledgements are drained without cancelling the commit. An unconfirmed interruption/rollback closes the connection and requires data verification before retrying. MySQL UPDATE affected counts report matched rows, including unchanged values.

Transaction guarantees follow the server: nontransactional trigger writes and external side effects cannot be undone by a savepoint. Rollback warnings are surfaced rather than reported as atomic success. Server formatting/encoding changes may produce conservative conflicts; refresh before editing.

The table Structure view shows native constraint and user-trigger metadata. PostgreSQL provides constraint definitions and trigger firing modes; internal enforcement triggers are excluded. MySQL/MariaDB lists constraint names/types and shows their definitions in the table DDL; trigger timing, event and body are displayed without pretending to be a complete backup script. SQLite exposes constraint definitions through its original table DDL and user triggers through sqlite_schema. NULLability remains in the column list. No automatic trigger execution or schema modification occurs during inspection. Metadata visibility follows connection permissions, so an empty list does not prove that a table has no triggers. PostgreSQL trigger functions, structured SQLite CHECK extraction, schema editing and statistics remain pending.

Relationship diagrams use native foreign-key column mappings on SQLite (main schema), PostgreSQL and MySQL/MariaDB, including composite and self-referencing keys. The desktop supports saved layouts, pan/zoom, manual/grid layout and native SVG export. Table selection bounds the diagram to a focused schema area; broader engine support and large-catalog performance validation remain pending. See [diagram behavior and limits](DIAGRAMS.md).

CSV and JSON imports append into editable SQLite/PostgreSQL/MySQL/MariaDB InnoDB tables through the same bounded transaction/savepoint writer. JSON supports standard object arrays and the app's explicit typed JSON export format, including positional duplicate source names. NULL and exact number tokens stay in Rust; destination database coercion rules still apply. Real four-engine contracts verify late parse/EOF failures roll back written batches and typed export roundtrips remain pending inside manual transactions. See [the import guide](IMPORTS.md) for input shapes, bounds and numeric limits. SQL scripts run from native-picked immutable snapshots with full preflight, mandatory review, completed-statement progress, deadlines/cancellation and the native connection lock held across the file. They preserve script transaction commands and report partial execution rather than promising whole-file rollback. SQL exports retain the source dialect for identifier, text and binary syntax; real four-engine roundtrips pass. Native desktop validation is listed separately in the validation log. JSONL imports remain pending.

DuckDB source builds add the native local-file workflow described in [the DuckDB guide](DUCKDB.md). The existing downloadable Preview 1 does not contain DuckDB. Its native database engine enforces read-only file access, and automatic extension installation/loading plus external file/network SQL access are disabled. Grid editing, file imports, plan-tree decoding and diagrams remain unsupported in this first slice. Decimal and top-level 128-bit integers are preserved exactly; unsupported native/container representations require a VARCHAR cast. Windows/Linux DuckDB workflows and package footprint remain pending.
