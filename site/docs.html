From your first connection to your next CSV import. This guide covers the currently implemented desktop workflow.

01 / Run the preview

Install Rust stable, Node.js 22.12+ and the Tauri prerequisites for your platform. Linux additionally needs Secret Service/DBus development libraries. Remembering a password requires an unlocked OS keychain.

TERMINAL
git clone https://github.com/OthmaneBlial/klyndb.git
cd klyndb/apps/desktop
npm ci
npm run tauri dev

To build a native package from the desktop directory:

BUILD
npm run tauri build

Development preview: native workflows are currently verified on macOS. Public downloadable releases and current Windows/Linux package validation remain pending.

02 / Connect to a database

Choose New connection, pick PostgreSQL, MySQL, MariaDB or SQLite and enter a connection URL or select a local SQLite file. Use Test connection before saving. Add an environment label and enable read-only mode when needed.

Server passwords are stored separately from connection metadata in your OS keychain. TLS verification is enabled by default. See the security model for local history and connection details.

For private servers, expand TLS & certificates and choose a public PEM/DER CA file through the native picker, then test and connect. Certificate and hostname checks stay enabled. Keep the saved file available for reconnects; a custom CA requires verified TLS. When your server requires mutual TLS, choose a PKCS#12 client identity and enter its separate certificate password. You can remember that password in the OS keychain. Private keys stay in the native TLS layer. SSH remains planned. Read the TLS guide for setup and limits.

Once connected, open a table from the explorer or create an SQL tab. Tables expose data and structure, including columns, indexes, foreign keys, constraints, user triggers and available table DDL. PostgreSQL exposes native constraint definitions and trigger firing modes; SQLite and MySQL/MariaDB show constraint definitions in table DDL. Trigger visibility follows your database permissions.

03 / Write SQL

Run the current statement, a selected range or the entire SQL file. Results stream from Rust into a disk-backed spool; the virtualized grid reads bounded pages.

ShortcutAction
Cmd/Ctrl + EnterRun selection or current statement
Cmd/Ctrl + KOpen command palette
Shift + Cmd/Ctrl + FFormat SQL
Cmd/Ctrl + SSave query

Settings control query timeout, row limit, theme and editor font size. Table views offer Database controls for server-side column filters, sorting and 100/250/500-row pages. Apply the controls to run a fresh query; the SQL appears in the editor. Primary keys break sort ties, but concurrent writes can shift page boundaries. The grid’s separate quick text filter and column-header sorting apply only to the fetched page. Arbitrary SQL tabs keep their existing result-spool pages. Read the table browsing guide for details.

04 / Review your changes

On editable base tables, stage updates, inserts and deletions, then review and apply the batch. Klyndb uses bound values and checks the old row values to detect conflicts. Generated columns are protected.

Grid editing supports SQLite, PostgreSQL and MySQL/MariaDB InnoDB tables. Updates and deletes need an appropriate primary key. Views and nontransactional MySQL tables are not staged-write destinations.

Use BEGIN, COMMIT and ROLLBACK in the SQL editor to manage manual transactions. Successful imports or edits inside an existing transaction remain uncommitted. The status indicator reflects the native session state.

05 / Move your data

CSV import

  1. Open an editable table and choose Import CSV.
  2. Choose a UTF-8 CSV with a header row using the native file picker.
  3. Set the separator, optional NULL token and whitespace options. Update the preview after changing parsing options.
  4. Map each source field to an existing destination column, or ignore it. Review value types and sample records.
  5. For a production connection, confirm that you reviewed the file and mapping. Choose Append rows.

Progress shows parsed records; final inserted rows appear after native completion. Cancellation waits for database and parser cleanup. Imports append data rather than replacing a table.

Files are limited to 512 MiB; quoted multiline fields, UTF-8 BOM and comma, semicolon, tab or pipe separators are supported. JSON and SQL file import remain planned. Read the complete import guide for limits and transaction behavior.

Export

Choose Export from a completed result set, select CSV, JSON, JSONL, SQL INSERT or Markdown, and save through the native dialog. Rust streams the retained result without copying the full dataset into the interface.

06 / Understand execution

Choose Explain for a native estimated plan. Expand the tree, inspect raw output and review server messages. Where supported, runtime analysis requires confirmation because it executes the query and its side effects.

Actual packaged macOS workflow with a disposable MySQL database.

SQLite exposes QUERY PLAN without invented runtime timings. See the execution-plan guide for each engine’s behavior.

07 / Explore relationships

Choose Relationships above a connected database’s table list. Select tables and load their native foreign keys, including composite keys and self-references. Drag tables or the background, zoom and use Fit to explore the selected area.

Save a local layout for that connection and reopen it with fresh metadata. Export the full displayed diagram as SVG through the native save dialog. Loading reads metadata, without scanning table rows or modifying your database.

Diagrams support SQLite, PostgreSQL, MySQL and MariaDB. Start with a focused area: up to 50 tables and 2,000 columns per diagram. Read the diagram guide for limits and controls.

Preview & support

Klyndb already supports common relational workflows. It does not yet cover every DBeaver feature. SSH tunnels, additional drivers, broader metadata and verified release packages remain on the roadmap.

Try it on a development database. If something fails, report a reproducible issue with your engine, platform and steps, excluding passwords and sensitive data.
